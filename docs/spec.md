# 仕様書

アプリの「何を・どう動かすか」を書く。AIは作業の前に必ずここを読む。

## 目的

スマホの縦画面で遊べるWebゲーム。短い指示や効果音の中から、鳴ってはいけない音だけを指で押さえて静かにさせる、新しい遊び方で結果を共有できる。（元のメモ：見たことない遊び方で、思わず人に送りたくなる Web ゲーム（ジャンルはおまかせ））

## 前提

- 使う人・使う場面（デザイン担当の分析。推定を含む）：
  - 使う人：X や TikTok で流れてきた動画・結果画像を見て、スマホでリンクを開いた人（説明を読まずに遊び始める）
  - 使う場面：電車や寝る前に縦持ちで1回 30〜70 秒、親指1〜2本で遊ぶ。負けたらすぐもう一度
  - 結果：「◯:◯◯ に起きちゃった」と称号の1枚をスクショするか、共有ボタンで友だちに送って張り合う
  - PC では、マウスか、音の横に出るキー（A S D F J K L）を押さえて遊ぶ
- 技術：TypeScript・Vite（Canvas／WebGL）、テストはVitest。Vercel で公開する（スマホ・PC のブラウザで遊ぶ）

### 今夜のお題

- 同じ夜（音の出る順番・場所）を全員で遊び、点や時刻を友だちと比べられるようにする遊び方
- 種：日本時間（Asia/Tokyo）の暦日（年・月・日）から決める。同じ日なら端末や時刻が違っても同じ種、日本時間の0時を過ぎると別の種になる（`src/lib/daily.ts` の `dailySeed`）
- 同じ並びが保証されるのは、何も押さないとき（押す・押さないで乱数の使われ方が変わるため）。点の比べ合いには足りるとする
- タイトル：主ボタン「夜をはじめる」（今までどおり毎回ランダムな夜）の上に、副ボタン「今夜のお題 11/3」（日本時間の今日の日付）を出す。押すとその日の種で始める。キーボード（Tab → Enter／Space）でも押せる
- 「もう一度」（結果の画面、R キーも同じ）：直前と同じ種類で始める。お題で遊んだ回はお題（そのとき日付が変わっていれば、新しい日のお題）、ランダムの回はランダム
- 結果の1枚と共有文：お題で遊んだ回だけ「今夜のお題 11/3」を出す。ランダムの回は今までと同じ
- やらない：ランキング・サーバー・点の保存・1日1回の制限・URL で種を指定・過去の日のお題

### ゲームパッド

- PC で、キーと同じ遊び方をゲームパッド（Gamepad API）でもできる。ゲームの中身（`src/lib/game.ts`）は変えない。対応は標準配置（`gamepad.mapping === "standard"`）だけ。標準でないものは無視する
- 割り当て：ボタン 0〜8 を `KEYS` の先頭から順（A S D F J K L G H）に割り当てる。どの音がどのキーになるかは今までどおり。ボタン名は 0〜3＝「A B X Y」、4〜8＝「LB RB LT RT 戻」（`src/lib/gamepad.ts`）
- 遊ぶ時：ボタンを押している間だけ、そのキーの音を押さえる（キーの押す・離すと同じ処理）。複数のボタンで同時に複数の音を押さえられる。「音を消す」「一時停止」にあたるボタンは無い
- タイトル：いずれかのボタンで「夜をはじめる」（Enter に相当）。結果：いずれかのボタンで「もう一度」（R に相当）。つないだ時にすでに押されていたボタンは「押した」に数えない
- つないだ時の表示：つながっている間、音の横のキー文字を割り当てたボタン名に置き換える。キーボード・タッチ・マウスは今までどおり使える
- ウィンドウのフォーカスが外れた時、ゲームパッドが抜かれた時は、押さえている音を離す。`navigator.getGamepads` が無い環境では、今までと同じに動く
- やらない：割り当ての変更、振動、スティック・十字キー

### 結果

- 「結果を共有」を押すと、結果の1枚を PNG 画像にして渡す。画像は画面の大きさに関係なく、固定の構図（390×700 論理px の 2 倍＝780×1400）で作る。ボタン・音を消すボタン・トースト・PC の両脇の文字は入れない。アニメーションを終えた状態を描く
  1. 画像のファイル共有ができる環境（`navigator.canShare({ files })`）では、画像と共有の文（URL つき）を `navigator.share` で共有する
  2. できない環境では、画像を `mute-the-room.png` として保存し、「画像を保存しました」のトーストを出す
  3. 画像が作れない時は、これまでどおり文だけを共有（共有できなければコピー）する
- 共有の取り消しや失敗でエラーを出して止まらない
